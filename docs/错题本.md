# 错题本

> 记录这个项目里犯过的错、踩过的坑、以及必须记住的东西。
> 每天收工时追加一条，按日期往下写。
>
> **为什么值得写**：同一个坑踩两次才是真浪费。而且面试官最爱问「你遇到过什么问题、怎么解决的」——
> 这份东西就是你回答的素材库，比"我很努力"有用一百倍。

---

## 一、怎么用

每条按这个格式写：

```
### N. 一句话说清这是什么坑
- **现象**：屏幕上到底出现了什么（原样贴报错）
- **原因**：为什么会这样
- **记住**：下次遇到同类问题，先做什么
```

三条铁律：

1. **现象要贴原文**，不要凭记忆转述。报错文字是你将来搜索的关键词。
2. **原因要写到"为什么"**，不能只写"这样改就好了"。只记结论等于没记。
3. **记住那一行必须能执行**——写成"下次先 `cd` 到项目目录"，不要写"要注意路径"。

## 二、第 1–3 天（10/25 – 10/27）：环境与基础设施

### 1. 微软商店的"假 Python"
- **现象**：`python --version` 敲下去，**什么都不输出**，也不报错
- **原因**：`python` 指向 `WindowsApps\python.exe`，那是微软商店的占位程序，不是真 Python
- **记住**：装完 Python 第一件事是 `where.exe python`，确认路径在 `Python311\` 下，不在 `WindowsApps\` 下

### 2. Python 安装器报 0x80070005
- **现象**：`Error 0x80070005: Failed to create cache directory`
- **原因**：你在 Administrators 组里，但进程是**中完整性**（UAC 没提权），写不了 `Package Cache`
- **记住**：手工建目录没用。用 `Start-Process -Verb RunAs` 提权装，UAC 点「是」

### 3. HTTPS 全挂、HTTP 通
- **现象**：`schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030E)`
- **原因**：TLS 握手在沙箱里失败，但明文 HTTP 不受影响
- **记住**：网络问题先分清是 DNS、TLS 还是带宽。这次是 TLS，所以改用 http 镜像站

### 4. pip 卡了 13 分钟
- **现象**：`Downloading torch...` 之后一动不动
- **原因**：pypi.org 直连不通
- **记住**：**装包卡住超过 1 分钟就换镜像**，别干等。阿里云 `-i https://mirrors.aliyun.com/pypi/simple/` 实测秒装

### 5. `cv2.CAP_PROP_BUFFERSIZE` 对 RTSP 无效
- **现象**：`cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)` 返回 `False`，但**不抛异常**
- **原因**：FFmpeg 后端不支持这个参数，OpenCV 静默失败
- **记住**：OpenCV 里"设置了但没生效"非常常见。**每次 set 都要看返回值**

### 6. 笔记本摄像头的手动曝光是坏的
- **现象**：遍历 `EXPOSURE = -13 … +1`，画面亮度几乎不变（luma 全部 1~18，近乎全黑），且结果不可复现
- **原因**：这颗摄像头的驱动根本不支持手动曝光（虚拟设备常见）
- **记住**：**硬件能力不能假设，先写探针脚本测**。测不通就换方案（改用 `--auto` + 固定光照）

### 7. 按了键没反应
- **现象**：`cv2.waitKey` 在 PowerShell 里敲 `q` 退不出去
- **原因**：键盘事件只发给**拥有焦点的窗口**
- **记住**：任何 GUI 程序（OpenCV 窗口、labelme），**按键前先用鼠标点一下那个窗口**

### 8. `initdb: 目录不为空` / `pg_ctl: 已在运行` 不是失败
- **现象**：重跑安装步骤，跳出一堆「错误」
- **原因**：这些是**幂等性提示**——"你要做的事已经做过了"
- **记住**：看报错先问一句「这是错误，还是状态说明？」。很多"报错"其实是成功

### 9. `docker version` 客户端能跑、连不上引擎
- **现象**：`failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`
- **原因**：Docker Desktop 没启动。**客户端和守护进程是两个东西**
- **记住**：`psql` 能连是因为 `pg_ctl start` 过了；`docker` 能用是因为 Desktop 在跑。**先确认"服务端"活着**

## 三、第 4 天（10/27）：采图

### 10. 采了 41 张，0 张可用
- **现象**：手机/笔记本摄来的图，全是手持、宿舍背景、无缺陷
- **原因**：只想着"拍够数量"，没控制**拍摄条件**
- **记住**：**采集条件比算法重要**。固定相机、纯色背景、单一光源、工件占画面 70~80%，这四条缺一条数据就废

### 11. 笔记本摄像头没法俯拍桌面
- **现象**：拍出来的全是"举着纸对着脸"
- **原因**：笔记本摄像头在屏幕顶边，**只能朝前**，物理上拍不到平放的桌面
- **记住**：设计方案前先问「**相机放在哪、朝哪**」。物理约束卡死的东西，代码救不回来

### 12. 类别标错了
- **现象**：白纸 + 耳机充电盒的图被标成 `pcb`（电路板）
- **原因**：随手填了 CLI 参数
- **记住**：`--category` 是**工件的种类**，不是"我手边有什么"。填错类别 = 数据集直接废

### 13. 微信传图把分辨率压没了
- **现象**：原图 3024×4032，传到电脑变成 1280×1707
- **原因**：微信普通发送会压缩
- **记住**：**数据链路每一环都可能降质**。用数据线直传 `DCIM`，或至少勾「原图」

### 14. 同一张纸拆成两个 part_id = 数据泄漏
- **现象**：差点把同一工件的照片分到 train 和 val
- **原因**：划分单位搞错了——应该按**物理对象**分，不该按图片随机分
- **记住**：**分组单位是物理对象**。宁可两个工件合并（安全），也不要一个工件拆开（泄漏）

### 15. 把推断说成了观察
- **现象**：我断言"这 12 张是同一张纸"，实际是从入库参数**推断**的
- **原因**：没区分「我看到的事实」和「我基于假设推出的话」
- **记住**：说结论时标明来源——"我看到 X"还是"我推断 X"。**技术沟通里这两者的分量完全不同**

## 四、第 5 天（10/28）：数据库与标注

### 16. `duplicate column name: id`
- **现象**：建表失败，报列名重复
- **原因**：加了主键那行，**忘了删原来的 `id INTEGER,`**
- **记住**：**traceback 从下往上看**，最后一行才是真正原因。这次直接指明了重复的列名

### 17. 文件明明在，却 `FileNotFoundError`
- **现象**：`python -c "...open('db/insert_自己版.sql')"` 报找不到
- **原因**：实际文件名是 `insert_自己版.sql.txt`——记事本「另存为」时文件类型没改，Windows 又隐藏了扩展名
- **记住**：找不到文件时，先开「显示文件扩展名」看一眼真实文件名

### 18. 在 `C:\Windows\system32` 里跑项目命令
- **现象**：`can't open file 'C:\Windows\system32\src\data\prepare.py'`
- **原因**：管理员 PowerShell 默认工作目录是 system32
- **记住**：**每条命令前先 `cd 项目目录`**，或者把工作目录写进路径

### 19. 复制命令时把讲解里的箭头也复制了
- **现象**：`syntax error near "↑"`
- **原因**：文档里用 `↑` 指着"这一行"，被当成 SQL 执行了
- **记住**：**只复制代码行**，别复制带注释箭头的整段

### 20. `sharpness` 这个指标不可信
- **现象**：空白纸 sharp=32.3，同一张纸换个角度 sharp=635.5
- **原因**：Laplacian 方差统计的是**全图高频细节**，背景布料的织纹、纸张的倾斜边缘都会把它拉高，跟"纸面清不清晰"没关系
- **记住**：**任何指标都要问"它到底在测什么"**。验收清晰度靠放大 200% 肉眼看，不靠一个数字

### 21. 折痕不算缺陷
- **现象**：不确定纸上的折痕该不该标成 `scratch`
- **原因**：良品图上也有折痕
- **记住**：**缺陷的定义是「良品没有、不良品有」的差异**，不是"看起来难看"。标了良品也有的特征 → 过杀率爆表

### 22. BOM 隐形字符
- **现象**：`标签名 '\ufeffscratch' 不认识`，35 项报错，但 labelme 界面上显示的标签看起来完全正常
- **原因**：PowerShell `Set-Content -Encoding UTF8` 写的是 **UTF-8 with BOM**，labelme 把 BOM 读进了第一个标签名
- **记住**：`\ufeff` = BOM。**读写中文文本一律显式指定编码**，需要无 BOM 就用 `New-Object System.Text.UTF8Encoding($false)`

### 23. 控制台打 emoji 直接崩
- **现象**：`UnicodeEncodeError: 'gbk' codec can't encode character '\u2705'`
- **原因**：中文 Windows 控制台默认 GBK，编不出 emoji
- **记住**：**给 Windows 写脚本，控制台输出别用 emoji**。开头加 `sys.stdout.reconfigure(encoding="utf-8")` 兜底
