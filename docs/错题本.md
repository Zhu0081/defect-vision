# 错题本

> 记录这个项目里犯过的错、踩过的坑、以及必须记住的东西。
> 每天收工时追加一条，按日期往下写。
>
> **为什么值得写**：同一个坑踩两次才是真浪费。而且面试官最爱问「你遇到过什么问题、怎么解决的」——
> 这份东西就是你回答的素材库，比"我很努力"有用一百倍。

---

## 一、怎么用

每条按这个格式写：

```
### N. 一句话说清这是什么坑
- **现象**：屏幕上到底出现了什么（原样贴报错）
- **原因**：为什么会这样
- **记住**：下次遇到同类问题，先做什么
```

三条铁律：

1. **现象要贴原文**，不要凭记忆转述。报错文字是你将来搜索的关键词。
2. **原因要写到"为什么"**，不能只写"这样改就好了"。只记结论等于没记。
3. **记住那一行必须能执行**——写成"下次先 `cd` 到项目目录"，不要写"要注意路径"。

## 二、第 1–3 天（10/25 – 10/27）：环境与基础设施

### 1. 微软商店的"假 Python"
- **现象**：`python --version` 敲下去，**什么都不输出**，也不报错
- **原因**：`python` 指向 `WindowsApps\python.exe`，那是微软商店的占位程序，不是真 Python
- **记住**：装完 Python 第一件事是 `where.exe python`，确认路径在 `Python311\` 下，不在 `WindowsApps\` 下

### 2. Python 安装器报 0x80070005
- **现象**：`Error 0x80070005: Failed to create cache directory`
- **原因**：你在 Administrators 组里，但进程是**中完整性**（UAC 没提权），写不了 `Package Cache`
- **记住**：手工建目录没用。用 `Start-Process -Verb RunAs` 提权装，UAC 点「是」

### 3. HTTPS 全挂、HTTP 通
- **现象**：`schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030E)`
- **原因**：TLS 握手在沙箱里失败，但明文 HTTP 不受影响
- **记住**：网络问题先分清是 DNS、TLS 还是带宽。这次是 TLS，所以改用 http 镜像站

### 4. pip 卡了 13 分钟
- **现象**：`Downloading torch...` 之后一动不动
- **原因**：pypi.org 直连不通
- **记住**：**装包卡住超过 1 分钟就换镜像**，别干等。阿里云 `-i https://mirrors.aliyun.com/pypi/simple/` 实测秒装

### 5. `cv2.CAP_PROP_BUFFERSIZE` 对 RTSP 无效
- **现象**：`cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)` 返回 `False`，但**不抛异常**
- **原因**：FFmpeg 后端不支持这个参数，OpenCV 静默失败
- **记住**：OpenCV 里"设置了但没生效"非常常见。**每次 set 都要看返回值**

### 6. 笔记本摄像头的手动曝光是坏的
- **现象**：遍历 `EXPOSURE = -13 … +1`，画面亮度几乎不变（luma 全部 1~18，近乎全黑），且结果不可复现
- **原因**：这颗摄像头的驱动根本不支持手动曝光（虚拟设备常见）
- **记住**：**硬件能力不能假设，先写探针脚本测**。测不通就换方案（改用 `--auto` + 固定光照）

### 7. 按了键没反应
- **现象**：`cv2.waitKey` 在 PowerShell 里敲 `q` 退不出去
- **原因**：键盘事件只发给**拥有焦点的窗口**
- **记住**：任何 GUI 程序（OpenCV 窗口、labelme），**按键前先用鼠标点一下那个窗口**

### 8. `initdb: 目录不为空` / `pg_ctl: 已在运行` 不是失败
- **现象**：重跑安装步骤，跳出一堆「错误」
- **原因**：这些是**幂等性提示**——"你要做的事已经做过了"
- **记住**：看报错先问一句「这是错误，还是状态说明？」。很多"报错"其实是成功

### 9. `docker version` 客户端能跑、连不上引擎
- **现象**：`failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`
- **原因**：Docker Desktop 没启动。**客户端和守护进程是两个东西**
- **记住**：`psql` 能连是因为 `pg_ctl start` 过了；`docker` 能用是因为 Desktop 在跑。**先确认"服务端"活着**

## 三、第 4 天（10/27）：采图

### 10. 采了 41 张，0 张可用
- **现象**：手机/笔记本摄来的图，全是手持、宿舍背景、无缺陷
- **原因**：只想着"拍够数量"，没控制**拍摄条件**
- **记住**：**采集条件比算法重要**。固定相机、纯色背景、单一光源、工件占画面 70~80%，这四条缺一条数据就废

### 11. 笔记本摄像头没法俯拍桌面
- **现象**：拍出来的全是"举着纸对着脸"
- **原因**：笔记本摄像头在屏幕顶边，**只能朝前**，物理上拍不到平放的桌面
- **记住**：设计方案前先问「**相机放在哪、朝哪**」。物理约束卡死的东西，代码救不回来

### 12. 类别标错了
- **现象**：白纸 + 耳机充电盒的图被标成 `pcb`（电路板）
- **原因**：随手填了 CLI 参数
- **记住**：`--category` 是**工件的种类**，不是"我手边有什么"。填错类别 = 数据集直接废

### 13. 微信传图把分辨率压没了
- **现象**：原图 3024×4032，传到电脑变成 1280×1707
- **原因**：微信普通发送会压缩
- **记住**：**数据链路每一环都可能降质**。用数据线直传 `DCIM`，或至少勾「原图」

### 14. 同一张纸拆成两个 part_id = 数据泄漏
- **现象**：差点把同一工件的照片分到 train 和 val
- **原因**：划分单位搞错了——应该按**物理对象**分，不该按图片随机分
- **记住**：**分组单位是物理对象**。宁可两个工件合并（安全），也不要一个工件拆开（泄漏）

### 15. 把推断说成了观察
- **现象**：我断言"这 12 张是同一张纸"，实际是从入库参数**推断**的
- **原因**：没区分「我看到的事实」和「我基于假设推出的话」
- **记住**：说结论时标明来源——"我看到 X"还是"我推断 X"。**技术沟通里这两者的分量完全不同**

## 四、第 5 天（10/28）：数据库与标注

### 16. `duplicate column name: id`
- **现象**：建表失败，报列名重复
- **原因**：加了主键那行，**忘了删原来的 `id INTEGER,`**
- **记住**：**traceback 从下往上看**，最后一行才是真正原因。这次直接指明了重复的列名

### 17. 文件明明在，却 `FileNotFoundError`
- **现象**：`python -c "...open('db/insert_自己版.sql')"` 报找不到
- **原因**：实际文件名是 `insert_自己版.sql.txt`——记事本「另存为」时文件类型没改，Windows 又隐藏了扩展名
- **记住**：找不到文件时，先开「显示文件扩展名」看一眼真实文件名

### 18. 在 `C:\Windows\system32` 里跑项目命令
- **现象**：`can't open file 'C:\Windows\system32\src\data\prepare.py'`
- **原因**：管理员 PowerShell 默认工作目录是 system32
- **记住**：**每条命令前先 `cd 项目目录`**，或者把工作目录写进路径

### 19. 复制命令时把讲解里的箭头也复制了
- **现象**：`syntax error near "↑"`
- **原因**：文档里用 `↑` 指着"这一行"，被当成 SQL 执行了
- **记住**：**只复制代码行**，别复制带注释箭头的整段

### 20. `sharpness` 这个指标不可信
- **现象**：空白纸 sharp=32.3，同一张纸换个角度 sharp=635.5
- **原因**：Laplacian 方差统计的是**全图高频细节**，背景布料的织纹、纸张的倾斜边缘都会把它拉高，跟"纸面清不清晰"没关系
- **记住**：**任何指标都要问"它到底在测什么"**。验收清晰度靠放大 200% 肉眼看，不靠一个数字

### 21. 折痕不算缺陷
- **现象**：不确定纸上的折痕该不该标成 `scratch`
- **原因**：良品图上也有折痕
- **记住**：**缺陷的定义是「良品没有、不良品有」的差异**，不是"看起来难看"。标了良品也有的特征 → 过杀率爆表

### 22. BOM 隐形字符
- **现象**：`标签名 '\ufeffscratch' 不认识`，35 项报错，但 labelme 界面上显示的标签看起来完全正常
- **原因**：PowerShell `Set-Content -Encoding UTF8` 写的是 **UTF-8 with BOM**，labelme 把 BOM 读进了第一个标签名
- **记住**：`\ufeff` = BOM。**读写中文文本一律显式指定编码**，需要无 BOM 就用 `New-Object System.Text.UTF8Encoding($false)`

### 23. 控制台打 emoji 直接崩
- **现象**：`UnicodeEncodeError: 'gbk' codec can't encode character '\u2705'`
- **原因**：中文 Windows 控制台默认 GBK，编不出 emoji
- **记住**：**给 Windows 写脚本，控制台输出别用 emoji**。开头加 `sys.stdout.reconfigure(encoding="utf-8")` 兜底

## 五、第 6 天（10/28 晚 – 10/29 上午）：部署、性能与版本控制

### 24. `best.onnx` 比 `best.pt` 还大
- **现象**：`best.pt` 5.7 MB，导出的 `best.onnx` **11.2 MB**
- **原因**：ONNX 存的是**完整计算图 + 全部常量**，不做压缩；`.pt` 存的是权重 + 结构引用，有共享
- **记住**：**文件大 ≠ 跑得慢**，比的是推理耗时不是体积。实测宿主机 180 ms/张，其中纯推理只有 39 ms

### 25. 同一个缺陷被框了两次
- **现象**：网页上同一道划痕出现两条记录，置信度 0.660 和 0.657，框几乎重合
- **原因**：导出时 `nms=True` 用的是默认 **IoU=0.7**，而这两框实算 IoU 只有 **0.611**，低于阈值所以都没被抑制
- **记住**：**细长小目标的 IoU 天然偏低**，NMS 阈值要按目标形状调。改 `iou=0.5` 后同图 6 条 → 5 条

### 26. 阈值调不动模型的天花板
- **现象**：阈值从 0.05 一路调到 0.90，撕角那 5 张的检出率**始终是 0**
- **原因**：这 5 张的模型输出最高分只有 **0.014–0.150**，比良品（≤0.079）还低，再降阈值只会把良品一起误判
- **记住**：**阈值只能在"分得开的两个分布"之间调**。两边一重叠，就该回去补数据或换方法，别在阈值上耗

### 27. 分析脚本把主产物覆盖了
- **现象**：跑了 `--splits val` 之后，之前 val+test 的曲线图和表格没了
- **原因**：输出文件名写死，没有区分参数
- **记住**：**分析脚本的输出要么带参数名（`--tag`），要么干脆不许覆盖主产物**

### 28. 容器比宿主机慢 7.8 倍
- **现象**：同一套代码同一个模型，宿主机 180 ms/张，容器里 1403 ms/张
- **原因**：compose 里用了 `./data/uploads_docker:/app/data/uploads` 的**绑定挂载**，Windows 下走 9p/virtiofs，实测分相计时里"写盘"一项就 **1219 ms**
- **记住**：**容器慢先分相计时**（解码 / 缩放 / 推理 / 落盘），别猜。改命名卷后 1403 → 180 ms

### 29. 容器里的 CPU 核数是假的
- **现象**：容器里 `os.cpu_count()` 返回 **20**（宿主机核数），但 `docker stats` 显示 CPU 只用了 16%
- **原因**：容器不隔离 CPU 拓扑，看到的是宿主机全量；onnxruntime 线程数设 0 会自动取满，反而线程打架
- **记住**：**容器里的资源视图不是真实配额**。要么 `--cpus=2` 限核，要么显式设 `intra_op_num_threads`

### 30. 装工具卡在没有输出的 10 分钟里
- **现象**：`winget install git` 跑了 10 分钟，**一个字都不输出**
- **原因**：安装器在等 UAC 提权弹窗，而没人去点
- **记住**：**静默安装卡住超过 2 分钟，先查是不是在等提权**。小工具优先用免安装版：MinGit 38 MB，npmmirror 下载 9.5 MB/s，4 秒搞定

### 31. MinGit 精简版没有 `ssh-keygen`
- **现象**：`C:\Users\24159\tools\git\usr\bin\ssh-keygen.exe` 不存在，但 `ssh.exe` 在里面
- **原因**：MinGit 是精简发行版，只带运行时需要的 ssh 组件
- **记住**：用系统的 `C:\Windows\System32\OpenSSH\ssh-keygen.exe`，别在 MinGit 里找

### 32. GitHub 打不开，改 DNS 没用
- **现象**：`https://github.com/signup` 白屏；`curl` 返回 `000`，15 秒超时
- **原因**：逐个试 8 个 GitHub 官方 IP，**全部卡在 TLS 握手**；但 DNS 解析出的是正确 IP，CDN（`githubassets.com`）0.45 秒就通 → 是 TLS 层被掐，不是域名污染
- **记住**：**"打不开"先分清是 DNS、TCP 还是 TLS**。三层的解法完全不同：DNS 改 hosts、TCP 换端口、TLS 只能换网络（手机热点）

### 33. `gitee.com/signup` 返回 405
- **现象**：打开 `https://gitee.com/signup` 白屏，`curl` 返回 `405`
- **原因**：Gitee 的注册页是 **`/register`**，`/signup` 这个路径存在但只接受 POST
- **记住**：**出现 404/405 先别怀疑网络**，很可能路径本身就不是那个

### 34. PowerShell 5.1 没有 `utf8NoBOM`
- **现象**：`Set-Content -Encoding utf8NoBOM` 报「无法将值转换为枚举 FileSystemCmdletProviderEncoding」
- **原因**：`utf8NoBOM` 是 **PowerShell 7（pwsh）** 才有的；Windows PowerShell **5.1** 只有 `UTF8`（带 BOM）
- **记住**：写脚本前先 `$PSVersionTable.PSVersion`。5.1 要无 BOM 就用 `New-Object System.Text.UTF8Encoding($false)`

### 35. 控制台乱码 ≠ 文件坏了
- **现象**：`Get-Content README.md` 显示「宸ヤ笟琛ㄩ潰缂洪櫡妫€娴?」这种乱码
- **原因**：文件是 **UTF-8**，控制台按 **GBK** 解码。文件本身一个字节都没错
- **记住**：**控制台乱码先换工具看**（VS Code / 编辑器），别急着"修"文件——很可能没坏

### 36. `.gitignore` 挡错了一层
- **现象**：`data/` 有 489 MB，`.gitignore` 里写了 `data/captured/`、`data/uploads/`，以为挡住了
- **原因**：只挡了两个**子目录**，`data/phone_inbox/`、`data/yolo/` 还在（只是被 `*.jpg` 顺手挡了）
- **记住**：**要挡就挡整层**。写 `data/`，不要写 `data/某个子目录/`

### 37. 自己起的服务，自己看不见
- **现象**：服务在后台跑着，浏览器能打开，但那个 PowerShell 窗口里**什么都看不到**；关掉窗口服务就没了
- **原因**：用 `Start-Process` 隐藏窗口起的
- **记住**：**长任务用独立可见窗口跑**。`Start-Job` 更坑——父进程一结束它就跟着死

## 六、第 7 天（10/29 晚）：INT8 量化与推送

### 38. opset 12 的模型直接量化，产出的是非法 ONNX

**现象**
```
Error Unrecognized attribute: axis for operator DequantizeLinear
Load model best_int8_static.onnx failed
```

**原因**：`DequantizeLinear` 的 `axis` 属性从 **opset 13** 才有。项目里的 ONNX 是
`nms=True, opset=12` 导出的（当初为兼容 RKNN 选的 12），量化器照着现在的写法
生成 QDQ 节点，模型就非法了。

**改法**：量化前先 `onnx.version_converter.convert_version(model, 13)`。
代码见 `src\deploy\quantize.py` 的 `ensure_opset13()`。

**教训**：算子的属性会随 opset 变。"导出来了"不等于"到处都能用"。

### 39. 量化后快了 1.28 倍，然后所有缺陷都检测不到

**现象**：全算子静态量化，p50 从 32 ms 降到 23 ms。逐图对比才发现，
5 张缺陷图的输出置信度**全部变成 0**，25 张图判定一致率只有 80%。

**原因**：这个 ONNX 把 NMS 烘进图里了。全算子量化把"置信度 → TopK →
NonMaxSuppression"整条通路的分数也量化了，解量化回来是 0，
NMS 的 `score_threshold=0.25` 就把所有框全过滤掉。

**改法**：`quantize_static(..., op_types_to_quantize=['Conv'])`，
只量化卷积。判定一致率回到 100%，平均置信度偏移 0.87%。

**教训（最贵的一条）**：
**量化的风险不是变慢，是悄悄变差。**
只测延迟不跑精度，你会把一个"快了 30%、但什么都检不出"的模型当成优化成果交出去。
任何性能优化都必须配一个**行为不变的证据**。

完整数据见 `reports\量化对比.md`。

### 40. `git push origin main` 说找不到 origin

**现象**
```
fatal: 'origin' does not appear to be a git repository
fatal: Could not read from remote repository.
```

**原因**：这个仓库的远程叫 `gitee`，不叫 `origin`。
`git remote add gitee git@gitee.com:zhuzhengh/defect-vision.git` 建出来的是 gitee。
git **不会自动把第一个远程命名为 origin** —— 那只是个约定俗成的默认名。

**记住**：推之前先 `git remote -v` 看名字，再 `git push <名字> main`。
别名随便叫都行，但脚本/文档里写死了 `origin` 就会当场翻车。

### 41. 线程开得越多，INT8 反而越不划算

**现象**（同一张 640×640，50 次取中位数）

| 线程数 | FP32 | INT8（仅 Conv） | 加速比 |
|---|---|---|---|
| 1 | 116.11 ms | 94.11 ms | **1.23×** |
| 4 | 56.45 ms | 48.55 ms | 1.16× |
| 8 | 39.89 ms | 42.75 ms | 0.93× |
| 20（auto） | 32.07 ms | 38.42 ms | **0.83×** |

**原因**：线程多了以后，瓶颈从「算力」转向「内存带宽 + 线程调度」。
INT8 省下的是乘加运算，这时候用不上；而每个 Conv 前后多出来的
Quantize / Dequantize 转换开销，是实打实照付的。

**原来是这样**：量化加速的前提是**算力受限**。
核多到内存带宽成为瓶颈时，量化不但不加速，还可能变慢。

**记住**：报加速比必须写清楚「哪颗 CPU、几个线程」。
20 核笔记本上测出的 0.83× 和 RK3588 单 NPU 场景下的 2–4×，
测的根本不是同一件事。

## 七、第 8 天（10/30）：脚本与网络


### 42. PowerShell 的 `@"..."@` 会把 Python 代码改坏

**现象**
```
  File "<string>", line 13
    new41 = '''
            ^
SyntaxError: unterminated triple-quoted string literal (detected at line 42)
```
明明写了配对的三引号，Python 却报「未闭合」，而且报错行号跟实际对不上。

**原因**：用的是**双引号** here-string `@" ... "@`，这种是**会展开**的：
- 反引号 `` ` `` 是 PowerShell 的转义符
- `$` 是变量前缀

代码在 Python 看到之前，就已经被 PowerShell 改过了。

**记住**：往 PowerShell 里塞代码，按顺序选
1. `@'...'@`（**单引号** here-string，不展开）—— 最省事
2. 先写成 `.py` 文件，再 `python xxx.py` —— 最稳
3. 只写单行时才用 `python -c "..."`

**不要**用 `@"..."@` 包任何代码。

## 八、第 9 天（10/31 全天）：从 test 0.0037 到 0.904

这一天从「5 个工件、圆珠笔细笔迹」开始，到「24 工件、马克笔粗笔迹、跨工件 test 0.904」结束。
中间推倒重来两次：一次是人工分类错位，一次是把良/缺判据从肉眼换成像素数。
值得记的不是最后那个数，是两次重来时各自发现了什么。

### 43. 训练用 1280，推理用 640 —— 指标假性暴跌

`train.py --imgsz 1280` 训完，`detector.py` 默认还是 `imgsz=640`。等于把模型的视力砍一半，
实际部署出来的效果比测试指标差一大截。

**规则：推理尺寸必须等于训练尺寸。** 现在 `detector.py` 默认 1280，可用 `DV_IMGSZ` 覆盖。

### 44. 阈值扫描脚本默认加载的是基线 v1 权重

`threshold_sweep.py` 的 `--model` 默认值指向 `baseline_v1`。换了新模型忘了传参，
它会拿旧权重扫出一张"漏检 24%"的图。差点据此判断"模型不行"。

**规则：任何对比脚本，跑之前先打印它实际加载的权重路径。** 现在脚本会打印推理尺寸，
模型路径也应该一起打。

### 45. 人工分类索引和入库脚本排序不一致，标到了空白纸上

`ingest_phone.py` 排序用 `natural_key`（按文件名里的连续数字比大小），
我写分类表时用 `p.name`（纯字符串排序）。同一个文件夹，两种排序下"第 1 张"是两张不同的照片，
于是 `scratch_001.jpg` 打开是空白纸。

**教训：凡是要按序号引用文件，必须 import 同一个排序函数，不要各写各的。**
现在的做法是 `from ingest_phone import natural_key`。

### 46. 更好的良/缺判据：用可量化的指标，不用眼睛

一开始靠拼图肉眼判良品/缺陷，60 张里错了好几处，而且无法复核。

改成「纸面掩膜内、比局部背景暗 25 以上的像素数」：

| | 笔画像素数 |
|---|---|
| 良品（36 张） | 0 ~ 1369 |
| 缺陷（24 张） | 41590 ~ 88953 |

中间空了 4 万，一次分对。**判据能量化，就不该靠眼睛。**

### 47. 自动化标注只在"缺陷足够显眼"时成立

第一轮用圆珠笔，自动标注 24 张里只成 8 张，最后 2 张怎么调阈值都标不上；
换成马克笔后 24 张一次全中。

**同一个算法，效果差异完全来自数据本身 —— 这是在提醒你：先修数据，再修算法。**
### 48. `prepare.py` 拿第一张图的标签代表整个工件

```python
cat = rs[0]["label"]      # ← 一个工件的类别，看第一张图决定
```

早期每个工件清一色（要么全良品、要么全缺陷），所以没暴露。
10/31 的工件是「3 张良品 + 2 张缺陷」，第一张恰好是良品，
于是 p008–p020 全被判定成良品，`val` 直接报「没有缺陷工件」而校验失败。

**规则：一个集合的类别要按图片统计，不能拿任意一张代表全体。**
现在 `validate()` 与打印表都按图片计数。

### 49. PowerShell 5.1 的 `Get-ChildItem` 没有 `-File` / `-Directory`

```
Get-ChildItem : 找不到与参数名称“File”匹配的参数。
```

`-File` 是 PS 5.1 之后的语法糖。回滚脚本里用了它，整条命令挂掉，
导致文件既没搬回 drop，也没报出真实数字。

**规则：写回滚/清理脚本时，用 `Where-Object { -not $_.PSIsContainer }`，
它在所有版本上都能跑。** 拿不准就用最笨的写法。

### 50. `global` 必须写在函数里**第一次使用之前**

```
SyntaxError: name 'DARK_DELTA' is used prior to global declaration
```

在 `main()` 里先读了 `DARK_DELTA`，后面才写 `global DARK_DELTA`，Python 直接拒绝编译。

**规则：`global` 声明放在函数体第一行。** 报错信息里 "used prior to global declaration"
六个字已经说清楚了，不用去搜。

### 51. 缺陷在缩放后只剩 1.6 个像素 —— 采样率是硬约束

圆珠笔笔迹在原图约 10 px 宽。640 输入 → **1.6 px**；1280 输入 → 3.2 px。
3 mm 马克笔在原图约 20 px。640 → 3.2 px；1280 → **6.4 px**。

结果：圆珠笔版本不管怎么调（v2 0.031、v3 0.000），模型只能把整张纸框成缺陷；
换马克笔 + 1280 后 test mAP50 直接到 **0.904**。

**原来是这样：** 目标在进网络前就小于它能分辨的尺度时，这件事已经不是调参问题，
而是采样率问题。**动手前先算一遍「缺陷在输入分辨率下有几个像素」。**

### 52. 路径字段已经带了前缀，再拼一次就成了双层目录

标注图是这么拷的：

```powershell
Copy-Item "data\captured\$($r.relpath)" ...
```

但 `metadata.csv` 的 `relpath` 本身就是 `captured\light_side\card\xxx.jpg`，
拼完变成 `data\captured\captured\light_side\...`，一张都拷不到。

**规则：用别人的字段前先 `Write-Host` 打一条出来看看它到底长什么样。**
