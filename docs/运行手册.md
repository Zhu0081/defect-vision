> 目的：让你在**任何一天**（一周后、一个月后、答辩前一晚）都能在 3 分钟内把整套东西跑起来。
> 所有命令都可以直接复制粘贴。遇到报错先翻第 6 节。

## 1. 一分钟启动

### 第 1 步：开两个 PowerShell 窗口

**这是最重要的一条规矩。**

| 窗口 | 干什么 |
|---|---|
| **A（服务）** | 只跑服务，启动后**别碰**，除了 `Ctrl+C` 停它 |
| **B（命令）** | 发请求、查数据库、看日志 |

在窗口 A 里敲 `Start-Process powershell` 可以开窗口 B。

判断服务活没活，不要看日志，直接打 `/health`（见第 5 节）。

### 第 2 步：窗口 A —— 启动数据库 + 服务

```powershell
cd F:\defect-vision

# ① 启动 PostgreSQL（如果正在运行会提示 already running，忽略即可）
db\pg.bat start

# ② 指向 PostgreSQL（不设这行，服务会用 SQLite 的 data\defect.db）
$env:DV_DATABASE_URL = "postgresql+psycopg://postgres@localhost:5432/defect"

# ③ 启动服务
python -m uvicorn src.service.main:app --port 8000
```

看到这三行就算成功：

```
[detector] 没找到模型 F:\defect-vision\models\best.onnx，先用 MockDetector（结果是假的）
[startup] 数据库=postgresql  模型=mock-v0  mock=True
INFO:     Uvicorn running on http://127.0.0.1:8000
```

> `数据库=postgresql` 这行是**唯一**能确认你连对数据库的地方。
> 如果是 `数据库=sqlite`，说明第 ② 步的环境变量没设上（多半是换窗口了）。

### 第 3 步：窗口 B —— 冒烟测试

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

期望输出：

```
status     : ok
db         : postgresql
model_name : mock-v0
is_mock    : True
upload_dir : F:\defect-vision\data\uploads
```

## 3. 接口清单

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/` | **网页版演示页**（拖图上传、画框、看历史） |

| GET | `/records?limit=20` | 最近 N 条检测记录（主表，不含缺陷明细） |
| GET | `/records/{id}` | 单条详情（**含缺陷明细，内部就是 JOIN**） |
| GET | `/image/{id}` | 取回当时上传的原图（网页画框、历史缩略图都用它） |
| GET | `/stats` | 汇总：总数、不良数、平均耗时、模型名 |
| GET | `/report` | **混淆矩阵 / 漏检率 / 过杀率 / 节拍分位数** |

浏览器打开 **http://127.0.0.1:8000/docs** 可以直接点按钮测试。

### 网页版（2026-10-28 新增）

`src\service\static\index.html` —— 单个 HTML 文件，内联 CSS/JS，没有 node、没有打包工具。

| 功能 | 说明 |
|---|---|
| 拖拽/点选上传 | 也支持手机浏览器（同一 Wi-Fi 下用局域网 IP 访问） |
| 画框叠加 | 用百分比定位 div，不用 canvas；框坐标本身就是归一化到 [0,1] 的 |
| 结果卡片 | verdict / 缺陷数 / 最高置信度 / 耗时 / 模型名 |
| 明细表 | 每个缺陷的类型、置信度、位置 |
| 历史记录 | 最近 8 条，带缩略图，点开看 `/records/{id}` |
| **一键回放** | 打开 `http://127.0.0.1:8000/?auto=16` 就会自动用第 16 条记录的图重跑一遍（**录演示视频时用这个**） |

⚠ 已知问题：同一个缺陷偶尔会被框两次（如 0.660 和 0.657 两个几乎重合的框）。
原因是导出的 ONNX 里 NMS 的 IoU 阈值固定 0.7，两条框的 IoU 只有 0.6 左右，都活下来了。
修法：导出时加 `iou=0.5` 重新导出。

## 6. 报错速查

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `无法连接到远程服务器` | 服务没启动 / 已被 `Ctrl+C` 关掉 / 端口不对 | 窗口 A 的日志看最后一行；重跑第 2 步 |
| `[startup] 数据库=sqlite` | 环境变量没设，或设在了另一个窗口 | 在**跑服务那个窗口**重新 `$env:DV_DATABASE_URL=...` |
| `port 8000 is already in use` | 上一个服务没停干净 | `Get-NetTCPConnection -LocalPort 8000 \| Select OwningProcess` 找到 PID，`Stop-Process -Id <PID>` |
| `connection refused ... 5432` | PostgreSQL 没启动 | `db\pg.bat start` |
| `FATAL: database "defect" does not exist` | 库没建 | `F:\pgsql\pgsql\bin\createdb.exe -h 127.0.0.1 -U postgres defect` |
| `duplicate column name` | SQL 里写了两次同名列 | 删掉旧的那行 |
| `can't open file 'db\q.py'` | 当前目录不对 | 先 `cd F:\defect-vision`，再执行 |
| `unable to open database file` | 同上，或路径写成了相对的 | 先 `cd F:\defect-vision` |
| 中文在终端显示成乱码 | 编码 | `$env:PGCLIENTENCODING="UTF8"` |
| `SyntaxError: ... ↑` | 复制了我讲解里的箭头/标注符号 | 只复制代码块，别复制注释里的符号 |

### 关不掉的服务

```powershell
# 找出占 8000 端口的进程并杀掉
$pid = (Get-NetTCPConnection -LocalPort 8000).OwningProcess
Stop-Process -Id $pid -Force
```

### 导出命令（换模型时重跑这一句）

```powershell
cd F:\defect-vision
python -c "from ultralytics import YOLO; YOLO('runs/segment/baseline_v1/weights/best.pt').export(format='onnx', imgsz=640, opset=12, simplify=True, nms=True, device='cpu')"
Copy-Item runs\segment\baseline_v1\weights\best.onnx models\best.onnx -Force
```

### 三个必须记住的细节

| 细节 | 值 | 为什么重要 |
|---|---|---|
| `nms=True` 不能省 | 输出 `[1, 300, 38]` | 不加就是 `[1, 84, 8400]` 未解码的 DFL，得到一堆乱框 |
| 38 列 = 6 + 32 | 前 6 列是框，后 32 是 mask 系数 | 本项目只用框，mask 系数暂时丢掉 |
| 框坐标在 **640 画布上** | 不是原图像素 | 必须做反 letterbox，`(x - left) / r` 再除以原图宽高 |

|---|---|---|---|
| p004 划痕图 | `ng` | 3 | 173–207 ms |

## 10. Docker 装不装（结论：**已装好**，2026-10-27 更新）

之前我说"本机不支持 Docker"，**是错的**。实测结论：

| 项目 | 实测 |
|---|---|
| WSL | ✅ 3.0.3.0，内核 6.18.54.1-WSL2 |
| Ubuntu 发行版 | ✅ 22.04.1 LTS，能正常启动 |
| Docker 本身 | ❌ 从没装过 |

Docker Desktop 在 Windows 上只有两个依赖：**WSL2** 或 **Hyper-V**。你有 WSL2，且能跑起来 —— 所以**装得了**。

### 两条路

| 方案 | 装在哪 | 大小 | 耗时 | 适合 |
|---|---|---|---|---|
| **A. Docker Desktop** | Windows | ~600 MB | 15–30 分钟 | 想用 Windows 终端直接敲 `docker` |
| **B. Docker Engine** | WSL 的 Ubuntu 里 | ~200 MB | 10 分钟 | 想把 WSL 当主开发环境 |

**推荐 A**，因为你的 PowerShell 工作流已经建立，装完在同一个窗口就能 `docker build`。

### 装完的第一件事

```powershell
docker run --rm hello-world
```

看到 `Hello from Docker!` 就说明通了。

### 你现在离"能写进简历"还差什么

装好只是第一步。真正要交付的是 **`docker build` 成功一次 + 容器内服务能对外响应**。这个放到 W6（见 15 周计划），别现在做。

|---|---|
| 镜像 `defect-vision:0.1` | **731 MB** |

| 数据库容器内存 | 61 MB |

### ⚠ 最重要的一条经验：别往 Windows 目录 bind mount 写文件

第一版 `docker-compose.yml` 写的是：

```yaml
volumes:
  - ./data/uploads_docker:/app/data/uploads   # 宿主机目录
```

结果单次检测 **1403 ms**。分相拆开测：

| 环节 | 耗时 |
|---|---|
| 解码 2.8MB JPEG | 161 ms |
| 缩放到 640×640 | 3 ms |
| ONNX 推理 | 39 ms |
| 写**容器内盘** | 28 ms |
| 写**绑定的 Windows 目录** | **1219 ms** ← 元凶 |

Docker Desktop 在 Windows 上要经过一层 9p/virtiofs 转发，小文件写入被放大几十倍。

改成命名卷后：

```yaml
volumes:
  - uploads:/app/data/uploads
```

单次检测 **1403 ms → 180 ms**，快 **7.8 倍**。

> 面试可以这么讲：*"我把服务 Docker 化后发现延迟从 200ms 涨到 1.4s，拆开逐段计时定位到是 Windows 绑定挂载的写放大，换成命名卷后回到 180ms。"*

**代价**：命名卷里的图不在资源管理器里，要看得用 `docker cp` 或 `docker run -v`。日常调试用 bind mount、演示用命名卷，是个合理取舍。

### 容器里为什么是 8010

```yaml
ports:
  - "8010:8000"     # 宿主 8010 → 容器 8000
```

容器内部的 `localhost` 指的是**容器自己**，所以 `--host 0.0.0.0` 是必须的；数据库地址也不能写 `localhost`，必须写服务名 `db`：

```yaml
DV_DATABASE_URL: postgresql+psycopg://postgres:postgres@db:5432/defect
```

### 脚本的核心技巧：推理只跑一次

先按 `conf=0.01` 把所有框取出来，记下每张图的**最高置信度**；之后每个阈值只是拿这个分数比大小。

42 张 × 19 个阈值 = 798 次推理 → 变成 42 次推理。

### 当前结果（2026-10-28）

| 评估集合 | 推荐阈值 | 漏检率 | 过杀率 | 准确率 |
|---|---|---|---|---|
| val（见过的纸） | 0.05 | **0%** | **0%** | 100% |
| val + test | 0.10 | **20%** | 0% | 92% |

**为什么 val 那么漂亮而 val+test 漏检压不下去**：良品 15 张的最高分全部 ≤0.079，而划痕（val，见过）能到 0.96——分得开；撕角（test，没见过）只有 0.01–0.15，和良品糊在一起。所以是**双峰分布**，不是模型调参能救的。

> 面试话术：*"我扫了 0.05–0.95 共 19 个阈值，出「阈值 vs 漏检率/过杀率」曲线。验证集 100% 但测试集漏检卡在 20% 下不来，直方图显示撕角类样本的最高分和良品重叠——这说明问题在数据覆盖，不在阈值。"*

## 13. 一句话原则

> **一个窗口跑服务，另一个窗口发命令。**
> **不确定就先打 `/health`，不要凭感觉猜。**
> **查不到 ≠ 不存在 —— 探测失败先怀疑权限，别急着下结论。**
> **机器慢 7 倍时，先分段计时，别急着换模型。**
> **指标分不开时，先画分数分布直方图，别急着调阈值。**
