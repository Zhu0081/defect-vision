# 名词对照卡

> 面试前扫一眼。每个词都配上「在哪个文件里」「你做过什么」。

---

## 一、四个核心词

### 训练 / 推理

| | 训练 | 推理 |
|---|---|---|
| 输入 | 图片 + 标注（标准答案） | 只有图片 |
| 做什么 | 反复比对答案，**修改模型自己的参数** | 参数不动，只给结论 |
| 快慢 | 慢（本次：30 轮 / 4.5 分钟 / 17 张图） | 快（本次：180 ms / 1 张） |
| 在哪个文件 | `src/train/train.py` | `src/service/detector.py` |
| 命令 | `python src\train\train.py --epochs 30` | 网页点「开始检测」 |

一句话：**训练是学习，推理是考试。考试时不许改脑子。**

### ONNX / ONNX Runtime

- **ONNX** = 一种通用的模型文件格式。像 `.pdf`——谁都能打开，不挑软件。
- **ONNX Runtime** = 读这个格式的「播放器」。像 Adobe Reader。
- 为什么转换：不转的话，部署时必须装 PyTorch（2 GB+）。转了只装 onnxruntime（几十 MB），镜像才 731 MB。

| 文件 | 大小 | 谁用 |
|---|---|---|
| `best.pt` | 5.7 MB | 训练、评估（要 PyTorch） |
| `best.onnx` | 11.2 MB | 线上推理（不要 PyTorch） |

> 注意反直觉：ONNX **更大**。因为它存了完整的计算图。转 ONNX 不是为了变小，是为了**不再依赖 PyTorch**。

### FastAPI

Python 写接口的框架。`src/service/main.py` 里每个 `@app.post(...)` 就是一个「门口」：

```python
@app.post("/detect")
def detect(...):   # 有人往 /detect 发图片，就执行这里
```

启动命令：`python -m uvicorn src.service.main:app --port 8000`
（uvicorn 是「跑这个 FastAPI 应用」的服务器）

### PostgreSQL

数据库，在 `F:\pgsql`。每次检测写进去：

```sql
inspection     -- 一次检测一行：时间、几张缺陷、多少毫秒、模型名
defect_item    -- 一个缺陷一行：类别、置信度、坐标
```

**为什么两张表**：一次检测可能有 5 个缺陷 —— 这叫「一对多」。合成一张表的话，「时间/耗时」要重复写 5 遍，改一次就得改 5 行。

（你写过的 `JOIN` 就是把这两张表按 `inspection_id` 拼起来。）

## 二、点一下按钮，中间发生了什么

```
浏览器                把图片 POST 到 http://127.0.0.1:8000/detect
  ↓
FastAPI               main.py 的 @app.post("/detect") 接住
  ↓
detector.py           解码 JPEG → 缩放到 640×640 → 归一化到 0~1
  ↓
ONNX Runtime          跑 best.onnx，输出框和分数
  ↓
detector.py           坐标从 640 画布换算回原图 → 拼成 JSON
  ↓
PostgreSQL            写 inspection 一行 + defect_item 若干行
  ↓
FastAPI               把 JSON 返回浏览器
  ↓
index.html            用 JS 把框画成彩色方块
```

**八步。记住「浏览器 → 接线员 → 检测器 → 播放器 → 账本 → 浏览器」六段就够了。**

## 三、目录里的文件都是什么

| 路径 | 是什么 |
|---|---|
| `runs/segment/baseline_v1/` | 这一次训练的输出文件夹（名字来自 `--name baseline_v1`） |
| `runs/.../weights/best.pt` | 30 轮里**验证集最好的那一轮**的参数快照 |
| `runs/.../weights/last.pt` | 最后一轮（通常不用，容易过拟合） |
| `runs/.../results.csv` | 每轮的各项指标 |
| `models/yolo11n-seg.pt` | 官方预训练权重（下载来的，训练从它出发） |
| `models/best.onnx` | 部署用的成品 |
| `data/yolo/` | 图片和标注，分成 images/ 和 labels/ |
| `data/yolo/data.yaml` | 告诉训练脚本：图在哪、有几类、类名叫什么 |

`best.pt` 为什么叫 best：训练到后面模型会「背答案」，验证集分数先涨后跌。所以存最好那一刻，不存最后。

## 四、自测 10 题

1. 训练和推理，哪个会改模型参数？
2. 为什么不直接用 `best.pt` 上线？
3. 网页点「开始检测」后，第一个接到请求的是谁？
4. `inspection` 和 `defect_item` 为什么要分开？
5. `best.pt` 和 `last.pt` 的区别？
6. 为什么要先缩放到 640×640？
7. `uvicorn` 是干什么的？和 `FastAPI` 什么关系？
8. 模型输出了 5 个框，这 5 个框存在数据库哪个表？
9. `data.yaml` 是给谁看的？
10. 如果我要换一个新工件，从哪一步开始重做？

<details>
<summary>答案</summary>

1. 训练。
2. 要装 PyTorch（2 GB+）；ONNX 只要几十 MB 的 runtime。
3. FastAPI（uvicorn 起的那个服务）。
4. 一对多：一次检测可能有多个缺陷，分开存避免重复字段。
5. `best.pt` 是验证集分数最高的那轮，`last.pt` 是最后一轮（常过拟合）。
6. YOLO 输入尺寸固定，640 是最小档；太小漏小缺陷，太大 CPU 跑不动。
7. uvicorn 是「跑 FastAPI 应用的服务器」；FastAPI 是「写应用」的框架。
8. `defect_item`（一次检测一个 `inspection`，其中多个缺陷）。
9. 训练脚本（告诉它图在哪、几类、类名）。
10. 采图 → 标注 → `prepare.py` 重新划分 → `train.py` 重训 → 导出 ONNX。

</details>
