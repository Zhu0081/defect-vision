# 知识点地图（这个项目真正覆盖到的东西）

> 用途：面试前 30 分钟扫一遍。每个点都锚在**你动过的某个文件或某个数字**上，
> 不是教科书目录。
>
> 星级说明：
> - ★★★ 面试官大概率会问，必须能讲 30 秒
> - ★★  问到了要能接住
> - ★   知道有这么回事即可，答不上不扣分

## 一、数据层（`src\data\`）

| 知识点 | 一句话 | 项目锚点 | 星 |
|---|---|---|---|
| **数据泄漏** | 同一工件的光照/位移变体进了不同集合，模型等于背题 | 按 `part_id` 分组划分，随机划分虚高 15–25 点 | ★★★ |
| **目标尺度与采样率** | 目标在输入分辨率下小于能分辨的尺度时，调参无解 | 笔迹 10 px → 640 输入 1.6 px；换马克笔 + 1280 → 6.4 px，test 0.0037→0.904 | ★★★ |
| **归一化坐标** | YOLO 存 0–1 相对坐标，与图片尺寸无关 | 前端用百分比 div 画框，换分辨率不错位 | ★★ |
| **良品要有空 txt** | 无标注文件会被当成"未标注图"丢弃，不能算良品 | v3 数据里良品必须有 `card_p00X_good_00Y.txt`（空文件） | ★★★ |
| **多边形 vs 框** | 缺陷形状不规则，框会把背景算进去 | 用 `labelme` 画 polygon，能算面积/长宽比 | ★★ |
| **编码与 BOM** | UTF-8 BOM 会把 `\ufeff` 塞进第一个标签名 | 35 项标注全废，`'\ufeffscratch'` 不是 `'scratch'` | ★★ |
| **用可量化判据替代人眼** | 人判 60 张会错几处且无法复核 | 纸面内「比局部背景暗 25 的像素数」：良品 ≤1369，缺陷 ≥41590 | ★★ |

## 二、模型层（`src\train\train.py`）

| 知识点 | 一句话 | 项目锚点 | 星 |
|---|---|---|---|
| **训练 / 推理 / 评估的区别** | 训练改权重，推理不改；评估是用已知答案的题打分 | `--eval-only` 只加载 `best.pt` 打分 | ★★★ |
| **mAP50 与 mAP50-95** | 前者只要 IoU>0.5 就算对；后者对 0.5:0.05:0.95 十个阈值取平均，更严格 | 0.904 / 0.584 | ★★★ |
| **分割 vs 检测 vs 分类** | 分割给轮廓，检测给框，分类给标签 | 用 `-seg`，因为要算划痕长度 | ★★ |
| **过拟合与泛化** | 训练集分数高不代表能用，要看换新工件 | val 0.974 vs test 0.904（同分布内的诚实差距） | ★★★ |
| **置信度不是概率** | 它是排序分数，只用于和阈值比较 | 良品最高分全 ≤0.01，划痕 0.5–0.96 | ★★★ |
| **输入分辨率是超参** | 同时影响精度、速度、显存；训练与推理必须一致 | 1280 训练 / 640 推理 → 漏检从 0% 恶化到 24% | ★★★ |
| **阈值扫描** | 扫一串阈值，画漏检率–过杀率曲线，选工作点 | 19 个阈值，0.05–0.35 全 0% | ★★★ |

## 三、转换层（`src\deploy\`）

| 知识点 | 一句话 | 项目锚点 | 星 |
|---|---|---|---|
| **ONNX 是什么** | 与框架无关的计算图中间表示，用 IR 存算子+权重 | `best.onnx` 11.7 MB | ★★ |
| **opset** | 算子集版本，低版本不认识的属性会报 `Unrecognized attribute` | opset 12 的 `DequantizeLinear` 没有 `axis`，升 13 才行 | ★★ |
| **NMS 固化进图** | 导出时 `nms=True`，线上不用再写后处理 | `[1,300,38]` 输出：300 个框 × (4 坐标 + 1 分数 + 1 类 + 32 mask 系数) | ★★ |
| **IoU 与 NMS 抑制** | 两框交集/并集 > 阈值就干掉分低的那个 | 两个重合框 IoU=0.611，阈值 0.7 压不住，改 0.5 | ★★ |
| **INT8 量化** | 权重/激活转 int8，体积降 3–4 倍，速度看指令集 | 11.2 MB → 3.4 MB | ★★ |
| **量化不一定提速** | x86 无 VNNI 时，反量化开销可能抵消收益 | 动态 0.11×（变慢）、静态 1.28×、仅 Conv 1.23× | ★★ |
| **校准集** | 静态量化要用真实输入分布估激活范围 | 用 val 的 25 张做校准 | ★ |

## 四、服务层（`src\service\`）

| 知识点 | 一句话 | 项目锚点 | 星 |
|---|---|---|---|
| **REST 接口设计** | 动词交给方法，名词交给路径 | `POST /detect`、`GET /records/{id}`、`GET /report` | ★★★ |
| **一对多建模** | 一次检测一行，一个缺陷一行，用外键关联 | `inspection` 1—N `defect_item`，`ON DELETE CASCADE` | ★★★ |
| **幂等** | 重复执行不产生副作用 | `CREATE TABLE IF NOT EXISTS`，重跑不炸 | ★★ |
| **上传安全** | 先看 `Content-Length`，再边读边计数，不能先读进内存 | `_consume_and_check_upload`，超限抛 413 | ★★ |
| **失败要清理** | 文件落盘成功但写库失败，会留下孤儿文件 | `except: path.unlink(); raise` | ★★ |
| **p50 / p95 延迟** | 平均值会被极端值带偏，工线看分位数 | 280 ms / 320 ms | ★★ |
| **健康检查** | 容器要做 liveness 探针，否则"启动了"不等于"能服务" | `HEALTHCHECK` + compose `condition: service_healthy` | ★★ |

## 五、部署层（Docker）

| 知识点 | 一句话 | 项目锚点 | 星 |
|---|---|---|---|
| **镜像分层与缓存** | 先 COPY 依赖清单再 COPY 代码，改代码不重装包 | `requirements-docker.txt` 单独一层 | ★★ |
| **绑定挂载 vs 命名卷** | Windows 绑定挂载走 9p/virtiofs，小文件写放大严重 | 一张 2.8 MB 图写 1219 ms；换命名卷 1403→180 ms | ★★★ |
| **配置外置** | 密码/路径不能硬编码进镜像 | `.env.example` + `${POSTGRES_USER:-postgres}` | ★★ |
| **客户端 vs 守护进程** | `docker` 命令只是客户端，`dockerd` 没起就连不上 | `failed to connect ... npipe:////./pipe/dockerDesktopLinuxEngine` | ★★ |
| **容器内 CPU 核数** | 容器看到的是宿主核数，限制要靠 `--cpus` 或配置项 | `os.cpu_count()` 返回 20 | ★ |

## 六、工程习惯

| 知识点 | 一句话 | 项目锚点 | 星 |
|---|---|---|---|
| **Git 提交粒度** | 一次提交一件事，message 说"为什么" | `feat(model): baseline_v4 ...`（细笔迹→粗笔迹+1280） | ★★ |
| **回归测试的价值** | 读代码看不出、跑测试才暴露的 bug 才是真 bug | pytest 9 个用例逼出 `UploadFile.stream` 不存在、`relative_to` 抛错 | ★★★ |
| **logging 代替 print** | 有级别、有时间、可重定向 | `%(asctime)s %(levelname)-5s %(name)s` | ★ |
| **复现性** | 固定种子、固定版本、固定输入尺寸 | 同一条命令重跑指标一致 | ★ |
