# 标注规范 v1.0

> **适用范围**：`defect-vision` 项目自有采集数据（`data/captured/`）
> **任务类型**：实例分割（YOLO-seg）
> **一句话**：这份文档比训练脚本重要。80% 的效果来自数据，标注不一致 = 模型学不到东西 = 无法复现。

---

## 0. 先记住三条铁律

1. **类别编号一旦定下，永不改动。** 新增类别只能往后加（5、6、7…），不能插在中间、不能重排。
2. **划分数据集按「工件」分，不按「图片」分。** 这是最容易翻车的地方，见第 7 节。
3. **有争议的样本，截图存进 `docs/label_edge_cases/`，并在本文档追加一条规则。** 不要凭感觉标第二次。

---

## 1. 类别定义

| id | 英文 | 中文 | 定义 | 典型成因 |
|---|---|---|---|---|
| 0 | `scratch` | 划痕 | 表面线状材料缺失或损伤，长宽比明显 | 搬运刮擦、刀具碰伤 |
| 1 | `stain` | 脏污 | 表面附着异物或液体残留 | 油污、粉尘、指纹、水渍 |
| 2 | `missing` | 缺件 | 应有结构缺失 | 漏装螺丝、贴片脱落、孔未钻 |
| 3 | `deform` | 变形/破损 | 几何形状偏离、边缘崩缺 | 挤压、跌落、冲压不良 |
| 4 | `crack` | 裂纹 | **预留，本项目不标** | — |

**不要新增类别，除非现有 4 类确实装不下。** 每多一类，样本需求 +1/4，你的 15 周撑不住。

---

## 2. 判定边界（吵架重灾区，先定死）

产线标准是客户定的，你的项目里**必须自己定一条线并写进 README**——面试时这句"我定的是 X，理由是 Y"很值钱。

| 情况 | 标不标 | 规则 |
|---|---|---|
| 划痕 vs 裂纹 | 只标 `scratch` | 本项目不做裂纹；有分叉的也按划痕标 |
| 直径 < 2mm 的灰尘/手印 | **不标** | 写进规范：低于 2mm 视为良品 |
| 直径 ≥ 2mm 的脏污 | 标 `stain` | 用酒精能擦掉也算，因为产线不允许 |
| 不改变轮廓的轻微弯曲 | **不标** | 以"能否被卡尺检出"为界 |
| 边缘 1mm 内的崩缺 | 标 `deform` | 贴边也要标，这类最容易被漏 |
| 被遮挡 > 50% 的缺陷 | **不标** | 标了模型也学不会；另存一张进 `label_edge_cases/` |
| 一个缺陷但被工件棱线分成两块 | 标**一个** polygon | 允许跨棱线，不要拆 |
| 两个相邻但独立的划痕 | 标**两个** polygon | 中间要有明显断开 |
| 整个工件大面积烧焦/损毁 | **不标，删图** | 没有分割意义，且会污染训练 |

## 3. 工具

**推荐：X-AnyLabeling**（GitHub 开源，免费）

- 支持多边形标注、SAM 辅助分割（点一下就出轮廓，省一半时间）
- 可直接导出 **YOLO Segmentation** 格式
- 装法：`pip install anylabeling` 或下载 Release 的 exe

**备选：LabelMe**（导出 JSON 后自己转格式，多一步）

**不推荐：LabelImg**——只支持矩形框，分割任务不够用。

### 3.1 X-AnyLabeling 关键配置

| 项 | 设置 |
|---|---|
| 格式 | YOLO Segmentation |
| 自动保存 | 开 |
| 标签文件 | `labels/` 与 `images/` 同级同名 |
| 快捷键 | `Ctrl+N` 新建多边形、`Ctrl+S` 保存、`D` 下一张 |

### 3.2 导出后的标签格式（必须确认）

每行一个实例，**多边形坐标归一化到 [0,1]**：

```
0 0.512 0.334 0.548 0.341 0.551 0.377 0.509 0.372
```

- 第一个数是 `class_id`
- 后面是 `x1 y1 x2 y2 ...`，**必须是偶数个**，至少 3 个点（6 个数）
- 坐标除以图片宽高，范围 0~1

> ⚠️ 如果导出的是绝对像素坐标（大于 1 的数），说明格式选错了，YOLO 会静默训坏。

## 4. 标注规则（分割）

1. **多边形紧贴缺陷外轮廓**，不要贴到工件边缘、不要框一大片。
2. **每条边顶点 ≤ 10 个**。多标顶点不会更准，只会更慢。
3. **不允许两个 polygon 重叠**。重叠会导致 mask 计算异常。
4. **小于 3×3 像素的区域不标**（模型学不到，只会增加噪声）。
5. **同一缺陷不要拆成多个 polygon**（见第 2 节表格）。
6. **标完整**：一张图里有 3 个缺陷就必须标 3 个，漏标 = 教模型"这个不是缺陷"，比标错更伤。
7. **不确定就不标，但记进 edge cases**。宁缺毋滥。

## 5. 良品怎么存

**良品也要有图，而且必须有对应的空标签文件。**

```
images/pcb_p001_good_001.jpg
labels/pcb_p001_good_001.txt      ← 空文件，0 字节
```

YOLO 要求 images 里每张图在 labels 里有同名 txt。**没有 txt 文件会被当成"没标注的图"跳过**，而不是"良品"。

怎么批量生成空 txt：

```bash
# 在项目根目录
for f in data/captured/light_top/pcb/*_good_*.jpg; do
  b=$(basename "$f" .jpg)
  : > "data/yolo/labels/train/${b}.txt"
done
```

（Windows 下用 PowerShell 或直接让 `src/data/prepare.py` 处理，别手搓。）

---

## 6. 目录与命名

采集端已经定好了命名，标注时**不要改名**：

```
<类别>_p<件号>_<good|缺陷类型>_<序号>.jpg
例：pcb_p001_scratch_001.jpg
```

原因：**工件号在文件名里，第 7 节的按工件划分才能实现**。改名 = 丢失分组信息 = 数据泄漏。

---

## 7. ★ 数据集划分：按工件分，不按图分

### 7.1 为什么

同一个工件的三张图（顶光/侧光/背光）**几乎一模一样**——同样的纹理、同样的位置、同样的缺陷。

如果你按图片随机分 7:2:1：

- 工件 001 的顶光图进了训练集，侧光图进了验证集
- 模型在训练时见过这个工件的**所有细节**
- 验证集指标虚高 **15~25 个点**
- 上线遇到新工件，效果断崖式下跌

**这就是数据泄漏（data leakage），面试官一问"你怎么划分的"就能听出来。**

### 7.2 正确做法

**按 `part_id` 分组划分**，同一个工件的所有光源、所有角度，必须全在同一个 split。

```
工件 001、002、003 … 020  → train
工件 021 … 026             → val
工件 027 … 030             → test
```

伪代码：

```python
import re
from collections import defaultdict

part = lambda name: re.search(r"_p(\d+)_", name).group(1)
groups = defaultdict(list)
for img in all_images:
    groups[part(img.name)].append(img)

parts = sorted(groups)
n = len(parts)
train_parts = parts[: int(n * 0.7)]
val_parts   = parts[int(n * 0.7): int(n * 0.85)]
test_parts  = parts[int(n * 0.85):]
```

产出：`data/splits/train.txt`、`val.txt`、`test.txt`（每行一个相对路径），训练时读这三个文件，别用随机 split。

### 7.3 评估还要再分组一次

**指标必须按光源分别报告**，不能只给一个总数。

| 光源 | 检出率 | 漏检率 | 过杀率 |
|---|---|---|---|
| 顶光 | | | |
| 侧光 | | | |
| 背光 | | | |

原因：这才是你那个"光源消融实验"的数据来源。给一个总数，就把整个差异化卖点弄丢了。

---

## 8. 别让模型学到"位置"

这是新手第二大坑：**所有良品都在画面正中间，所有缺陷都在左上角** → 模型学的是位置，不是缺陷。

必须做：

- 每次拍摄时把工件**平移 ±10%、旋转 ±10°**
- 同一工件至少拍 **5~8 个不同位置**
- 背景每次换一点（桌面换个垫纸、换个角度）

数据增强（翻转/旋转）**替代不了**真实采集的多样性——增强出来的图，光照和纹理还是同一套。

---

## 9. 质量控制

### 9.1 自检清单（每标完 50 张过一遍）

- [ ] 每个缺陷都标了，没有漏（尤其是贴边的）
- [ ] polygon 没贴到工件边缘外面
- [ ] 没有两个 polygon 重叠
- [ ] 类别选对了（划痕 vs 脏污最容易搞混）
- [ ] 极小区域（<3×3 px）已经剔除
- [ ] 良品都有对应的空 txt
- [ ] 文件名没有改过

### 9.2 抽检

**随机抽 10%，隔一天再用另一副眼睛标一遍**（自己标自己的，隔开时间才有效），比较差异：

- 一致率 < 90% → 说明规则不清，回第 2 节补规则，然后全部重审
- 一致率 ≥ 95% → 可以往下走

这一步只用 1 小时，但能救你后面两周的白工。

## 10. 常见错误 Top 8

| # | 错误 | 后果 | 修法 |
|---|---|---|---|
| 1 | 按图片随机划分 | 验证集虚高 20 点，上线崩 | 按 `part_id` 分组 |
| 2 | 良品没有空 txt | 良品被当"未标注"丢弃，模型只见过缺陷 | 批量生成空 txt |
| 3 | 坐标没归一化 | 训练 loss 直接异常 | 导出时选 YOLO Segmentation |
| 4 | 漏标部分缺陷 | 教模型"这个不是缺陷"，比标错更毒 | 自检清单 + 抽检 |
| 5 | 所有工件同一位置 | 模型学位置不学缺陷 | 拍摄时平移旋转 |
| 6 | 缺陷样本 < 10 个/类 | 该类完全学不会 | 每类至少 30 个实例 |
| 7 | 标了被遮挡 > 50% 的缺陷 | 引入噪声 | 不标，存 edge case |
| 8 | 改了文件名 | 丢工件号，无法分组 | 采集端命名规则不许改 |

## 11. 进度与工时（对齐 15 周计划）

| 阶段 | 时间 | 目标 | 工时 |
|---|---|---|---|
| W1 | 10/26 – 11/08 | 采 540 张（3 类 × 3 光源 × 60），标 100 张 | 约 6h 拍摄 + 4h 标注 |
| W2 | 11/09 – 11/15 | 累计标 200 张，跑通划分脚本 | 5h |
| W3–W4 | — | 跑训练，边训边补标到 400 张 | 6h |
| W5 | — | 无人监督线只要良品图（300 张，不标注） | 0h |

**工时估算**：一张 1080p、1~3 个缺陷的图，标注 **40~90 秒**。200 张 ≈ 3~5 小时。

> 标注是唯一不能"跑个脚本解决"的活，也是最容易半途而废的活。**分成每次 30 分钟的小块做**，别攒到最后一天。

## 12. 面试可能被问到的数据问题（提前想好答案）

1. 你的数据集怎么划分的？（答：按工件分组，防泄漏——这是加分项）
2. 每类多少样本？类别不平衡怎么处理？
3. 良品和缺陷的比例是多少？为什么？
4. 数据增强用了哪些？为什么不用更强的增强？
5. 标注一致性怎么保证的？
6. 你的缺陷定义是谁定的？（答：自己定了一条线，写进 README——诚实且专业）
7. 为什么用分割不用检测框？（答：缺陷面积/形状是判据，框丢信息）
8. 现场来了新类型的缺陷，模型没见过，怎么办？（答：无监督异常检测那条线就是干这个的）
