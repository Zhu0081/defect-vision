# 采集操作手册 · 校准怎么调、试拍怎么拍

> 这份是「手里拿着相机时照做」的现场手册。
> 判定标准和标注规则在 [标注规范.md](标注规范.md)，环境问题在 [环境搭建.md](环境搭建.md)。

## ⚠ 卡住先看：按键没反应 / 曝光调不动

### 先判断是哪种卡住

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 按 `]` `[` `空格` 完全没反应，终端也没输出 | **窗口没有键盘焦点** | 用鼠标点一下视频窗口，再按 |
| 终端的 `]` 变成了别的字符或没显示 | 焦点在终端，键被 PowerShell 吃了 | 同上 |
| 输出 `exposure = -6` 了，但画面还是一团黑 | **这台摄像头手动曝光是坏的** | 用 `--auto`，见下 |

判据：在视频窗口上按 `q`，窗口能关掉 → 焦点是对的，问题在相机那边。

### 实测结论：本机笔记本摄像头不支持手动曝光

| 模式 | 设定 | 实测 luma |
|---|---|---|
| 自动 | `CAP_PROP_AUTO_EXPOSURE = 0.75` | **84 ~ 87**（正常画面） |
| 手动 | `CAP_PROP_EXPOSURE` = -13 … +1 任意值 | **1 ~ 17**（几乎全黑） |

手动一开就掉到最暗，`--calibrate`、`--sweep`、`[ ]` 全都救不回来。
**这不是你操作错**，是驱动限制，很多笔记本摄像头和便宜 USB 摄像头都这样。

### 出路 A（现在就能拍）：全自动模式

```powershell
cd F:\defect-vision
python src\capture\grab.py --source 0 --auto --category pcb --part 001 --light top
```

曝光 / 对焦 / 白平衡全交给相机，你只管摆工件 + 按空格。

代价：自动曝光会随光线强弱自适应，**所以灯的位置和亮度全程绝对不许动**——动一次，这批数据的前后就不一致了。
CSV 的 `exposure` 列会写 `auto`；写报告/面试时如实说「相机不支持手动曝光，改用固定光源 + 自动曝光并记录亮度」，
这是**加分**（说明你知道数据一致性靠什么保证），不是减分。

### 出路 B（更好，0 元）：手机当相机

手机装 IP Webcam，App 里可以**手动锁曝光、锁对焦、锁白平衡**，画质和分辨率都碾压笔记本摄像头：

```powershell
python src\capture\grab.py --source http://<手机局域网IP>:8080/video --auto --category pcb --part 001 --light top
```

### 出路 C（实在要严谨的光源对比）

换一支 30–60 元的 UVC USB 摄像头，一般支持手动曝光；或接受 A 方案并把它作为「实验局限」写进报告。

### 开拍前的 3 秒体检

跑 `--auto`，看视频窗口左上角：

- `luma` 在 **60~180** 且 `sharp` **>30** → 可以拍
- `luma` < 40 → 太暗：台灯移到 30cm 内、正对工件
- 一直红字 `!! BLURRY` → 画面里根本没有工件（对着白墙调焦 Laplacian 只有个位数是正常的）

## 0. 开拍前：10 分钟物理布置（决定成败的一步）

**这一步的投入产出比高于后面所有代码。** 光线不稳、背景杂乱、工件角度乱变，模型学到的就是「哪张图长得像」，不是缺陷。

### 0.1 台账

| 要素 | 要求 | 0 预算做法 |
|---|---|---|
| **背景** | 纯色、哑光、无花纹无文字 | A4 白纸（亮工件）/ 黑色卡纸或黑 T 恤（暗工件） |
| **光源** | 单一、位置固定、亮度固定 | 一盏台灯。别用吸顶灯做主光，太散 |
| **环境光** | **必须消除** | 关房灯、拉窗帘。白天拍的和晚上拍的不能混在一起 |
| **相机位置** | 固定不动，垂直朝下或斜 15° | 书堆 + 橡皮筋，或手机支架。**绝对不要手持** |
| **工件与相机距离** | 让工件占画面宽度的 **70–80%** | 试一次量一下，之后固定 |
| **参照尺** | 可选，放把尺子拍 1 张存着 | 用来换算 mm/像素，写报告时用得上 |

### 0.2 为什么"手持"是致命的

手举着拍 200 张，会出现：
- 距离变化 → 同一个缺陷忽大忽小 → 模型学了尺度不变性，反而削弱了小缺陷信号
- 角度变化 → 同一工件的三种光源图对不上，你的光源对比实验直接作废
- 轻微抖动 → Laplacian 掉到 30 以下，脚本直接拒拍，白拍

### 0.3 三种光源怎么摆

```
顶光 (top)      侧光 (side)     背光 (back)
  💡               💡
  ↓                ↘
 ┌───┐            ┌───┐          💡
 │工件│ 45° 俯拍   │工件│          ↓
 └───┘            └───┘         ┌───┐
                                │工件│  透射
```
- **顶光**：抓表面脏污、色差，但反光强，容易过曝
- **侧光**（约 20–30° 掠射）：**抓划痕最有效**，划痕会拉出阴影。这是你的主光源
- **背光**：抓缺件、破孔、轮廓缺陷。需要半透明工件或留缝

每种光源都要单独固定位置，拍完一组不要动灯。

## 1. 第 1 步：校准（约 10 分钟，一次性）

```powershell
cd F:\defect-vision
python src\capture\grab.py --source 0 --calibrate --res 1920x1080
```

窗口里会实时显示两行关键数字。

### 1.1 看哪两个数

| 指示 | 目标值 | 含义 | 调法 |
|---|---|---|---|
| `luma`（平均亮度） | **110–150** | 画面整体灰阶，0–255 | 按 `]` 提高曝光，`[` 降低。一档约 ±2 |
| `sharpness` | **> 100** | Laplacian 方差，越大越锐 | 按 `f` 自动对焦一次后**锁住**；或前后移动 2–3cm |

### 1.2 三个必须知道的坑

**① sharpness 会骗人——画面里必须有工件**

Laplacian 方差测的是"边缘有多锐"。如果你对着**纯白纸**或**空桌面**调焦，整个画面平滑无纹理，sharpness 只有个位数，脚本会一直报 `!! BLURRY`。这不是对焦坏了，是**没有内容可测**。

> 正确做法：校准和拍摄全程，画面里都要有工件。别对着空背景调。

**② 亮度要"低一点"而不是"高一点"**

过曝（luma > 200）会把划痕的细节**永久烧掉**——像素饱和到 255 之后，再多的算法也救不回被削平的亮度差。欠曝只是噪声多一点，还能靠后期拉。

> 宁可 luma = 110，不要 luma = 190。

**③ 反光金属件会局部过曝**

金属片在顶光下会有一块镜面高光。处理办法：**换成侧光**，或者在灯前蒙一张白纸做柔光。别靠降曝光硬压——压下去别的地方就全黑了。

### 1.3 校准结束后要抄下来的东西

退出时脚本会打印类似：

```
建议: --exposure -5
```

**把这个数字抄到纸上/记事本**。之后每次拍都要带同一个值：

```powershell
python src\capture\grab.py --source 0 --category pcb --part 001 --light top --exposure -5 --res 1920x1080
```

换了光源位置、换了房间、换了时间段，都要**重新校准一次**并记录新的曝光值。

## 2. 第 2 步：试拍 30 张（约 20 分钟）

这次的目的**不是攒数据**，是验证三件事：

1. 曝光锁定后，亮度会不会自己漂（自动曝光真的关掉了吗）
2. 对焦锁住了吗（连拍 10 张 sharpness 稳定吗）
3. 缺陷在图上**人眼能不能看清**

### 2.1 拍什么

| 内容 | 张数 | 说明 |
|---|---|---|
| 良品 · 顶光 | 5 | 同一工件，动 5 个位置 |
| 良品 · 侧光 | 5 | 同上，换光源 |
| 划痕 · 侧光 | 8 | 侧光才看得见划痕 |
| 脏污 · 顶光 | 6 | 指纹、污渍、氧化 |
| 缺件 / 变形 | 6 | 有就拍，没有就用别的类别占位 |

**总数 30 张，覆盖 2 种以上光源、2 个以上工件。**

### 2.2 每张之间必须做的动作

每次按 `SPACE` 之前，**动一次工件**：

- 平移 ±10%（约 1–2 cm）
- 旋转 ±10°（约 5–10 度）
- 同一工件换 5–8 个位置

原因写在 [标注规范.md](标注规范.md)：不让模型把"缺陷在画面左下方"学成特征。这个动作现在做，比训练完发现模型只会认位置再返工便宜一百倍。

### 2.3 操作顺序（照着敲）

```powershell
cd F:\defect-vision

# 良品，顶光
python src\capture\grab.py --source 0 --category pcb --part 001 --light top --exposure -5 --res 1920x1080
# 窗口里：按 0 = 良品，按 SPACE 拍，每张前挪一下工件

# 换侧光，同一工件
python src\capture\grab.py --source 0 --category pcb --part 001 --light side --exposure -5 --res 1920x1080
# 按 1 = 划痕，拍 8 张

# 换工件
python src\capture\grab.py --source 0 --category metal --part 002 --light top --exposure -5 --res 1920x1080
```

> `--part` 一定要换！同一个 `part_id` 代表"同一个物理工件"，划分数据集时整组进训练集或验证集。**两个不同工件用了同一个编号，数据泄漏；同一个工件的三组图用了不同编号，验证集指标虚低。**

### 2.4 拍的过程中每 5 张回看一眼

盯 `luma` 那个数：

- 波动在 **±5** 以内 → 正常，继续
- 波动超过 **10%** → 屏幕会红字 `LUMA DRIFT`，说明曝光没锁住或灯在变（比如有人开了门、台灯接触不良）。**停下来重跑 `--calibrate`**

## 3. 第 3 步：自检（约 5 分钟）

拍完先别看图，先看数。**把下面整段复制进 PowerShell 一次跑完：**

```powershell
$rows = Import-Csv F:\defect-vision\data\captured\metadata.csv
"总张数     = $($rows.Count)"
"亮度异常   = $(@($rows | Where-Object { $_.luma_ok -ne '1' }).Count)"
"图片文件   = $((Get-ChildItem F:\defect-vision\data\captured -Recurse -Filter *.jpg).Count)"
""
$rows | Group-Object light | ForEach-Object {
    $l  = $_.Group | ForEach-Object { [double]$_.luma_mean }
    $s  = $_.Group | ForEach-Object { [double]$_.sharpness } | Sort-Object
    $lm = ($l | Measure-Object -Average).Average
    $sd = [math]::Sqrt((($l | ForEach-Object { ($_-$lm)*($_-$lm) }) | Measure-Object -Sum).Sum / $l.Count)
    "{0,-5} n={1,3}  luma={2,6:N1} ±{3,4:N1}  sharpness中位数={4,6:N0}" -f `
        $_.Name, $l.Count, $lm, $sd, $s[[int]($s.Count/2)]
}
```

输出长这样就是健康的：

```
总张数     = 31
亮度异常   = 1
图片文件   = 31

side  n= 13  luma= 128.4 ± 2.1  sharpness中位数=  412
top   n= 18  luma= 134.0 ± 3.4  sharpness中位数=  287
```

### 3.1 四个判断数字

| 指标 | 合格线 | 不达标怎么办 |
|---|---|---|
| `luma_ok=0` 的比例 | **< 10%** | 重校准，检查灯是否稳定 |
| 同一光源下 luma 标准差 | **< 5** | 曝光没锁住，重来 |
| sharpness 中位数 | **> 100** | 对焦没锁 / 距离太远 |
| 缺陷肉眼可见 | 放大到 100% 还能分辨 | 拉近、换侧光、或者这个缺陷太小不值得标 |

### 3.2 最重要的一条：人眼判据

**把图放大到 100%，你自己看不出来的缺陷，模型也学不会。**

这不是"模型更强就能看出来"，是无监督/有监督都逃不掉的物理下限：像素里没有的信息，任何网络都变不出来。拍不出来就换光源、拉近距离、换更大的缺陷样本——三选一，不要指望训练解决。

## 4. 翻车对照表

| 现象 | 原因 | 修法 |
|---|---|---|
| 一直 `!! BLURRY`，但画面明明清楚 | 对着空背景，没有纹理可测 | 让工件进画面 |
| luma 调到 150 了图还是很暗 | 台灯功率不够 / 距离太远 | 灯移近到 30cm 内 |
| 画面一半亮一半暗 | 单侧光源，光照不均 | 加白纸反光板，或灯移到正上方 |
| 金属件一片死白 | 镜面反光过曝 | 换侧光 / 灯前蒙白纸柔光 |
| 每张 luma 都不一样 | 自动曝光没关掉 | 检查是否用了 `--no-mjpg` 或换了后端；重跑 `--calibrate` |
| 图片存到了奇怪的地方 | 没在 `F:\defect-vision` 下运行 | `cd F:\defect-vision` 再跑 |
| 文件序号从头开始 | 换了 `--part` 或 `--light`（正常） | 断点续采是同参数才续号 |

- [ ] `data/captured/metadata.csv` 有 **30 行左右**数据
- [ ] `luma_ok=0` 的行数 **≤ 3**
- [ ] 随便挑 3 张，`sharpness` 都 **> 100**
- [ ] 打开 3 张缺陷图，100% 放大后**你能指出来缺陷在哪**

**没做到就停下来调，不要硬拍。** 前面拍歪的 100 张，后面要花 3 小时重拍 + 重标，还可能在训练时给你一个"为什么指标上不去"的假象。
