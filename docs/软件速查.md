## 1. PowerShell —— 所有命令的入口

**定位**：Windows 的"命令行"。你在这里敲的所有命令，本质都是让某个程序去干活。

**怎么开**

```
Win + R  →  输入 powershell  →  回车
```

> ⚠️ 注意：**管理员窗口**打开时默认停在 `C:\Windows\System32`，
> 相对路径会以它为准，于是 `python src\xxx.py` 会报 `can't open file`。
> 你已经有 profile 自动跳转了，但**每次开窗口第一件事还是 `cd F:\defect-vision`**。

**三条救命命令**

```powershell
Get-Location                    # 我现在在哪（等价于 pwd）
Get-ChildItem                   # 这层有什么（等价于 ls / dir）
Get-NetTCPConnection -LocalPort 8000 -State Listen   # 8000 端口被谁占了
```

**常用的另外几条**

| 想干什么 | 命令 |
|---|---|
| 进目录 | `cd F:\defect-vision` |
| 回上一级 | `cd ..` |
| 看文件内容前 20 行 | `Get-Content 文件 -TotalCount 20` |
| 实时跟日志 | `Get-Content 文件 -Wait -Tail 20` |
| 找进程 | `Get-Process python` |
| 杀进程 | `Stop-Process -Id 1234 -Force` |
| 设临时环境变量 | `$env:DV_IMGSZ = "640"` |
| 看环境变量 | `$env:PATH` |
| 判断文件在不在 | `Test-Path F:\defect-vision\README.md` |
| 统计文件数 | `(Get-ChildItem 目录).Count` |

**常见报错**

| 报错 | 意思 | 怎么办 |
|---|---|---|
| `无法将"xxx"项识别为 cmdlet...` | 这个程序不在 PATH 里 | 用全路径，或先 `cd` 到能找得到的地方 |
| `can't open file 'C:\Windows\System32\src\...'` | 你在 system32 里跑相对路径 | `cd` 到项目根目录 |
| `无法加载文件 ... 因为在此系统上禁止运行脚本` | 执行策略拦了 | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |

## 2. Python 3.11 + pip

**定位**：整个项目的执行引擎。训练、推理、起服务、标注工具，全是 Python 脚本。

**位置**

```
C:\Users\24159\AppData\Local\Programs\Python\Python311\python.exe
版本：Python 3.11.9
```

**三条救命命令**

```powershell
python --version                          # 装了没、什么版本
python -m pip list                        # 装了什么包
python -m uvicorn src.service.main:app --port 8000   # 起服务
```

**为什么是 `python -m pip` 而不是 `pip`**

`pip` 可能指向另一个 Python 环境。`python -m pip` 是"用**这个** python 去跑它自己的 pip"，
装到哪里一定对得上。**面试被问"你怎么保证包装对了环境"，这就是答案。**

**常用的另外几条**

| 想干什么 | 命令 |
|---|---|
| 装包（走阿里云镜像） | `python -m pip install 包名 -i https://mirrors.aliyun.com/pypi/simple/` |
| 看某个包版本 | `python -m pip show ultralytics` |
| 卸载 | `python -m pip uninstall 包名` |
| 跑脚本 | `python src\train\train.py --epochs 30` |
| 跑一行代码 | `python -c "import torch; print(torch.__version__)"` |

**别名陷阱**

同一个项目里有 `src\service\main.py`，也有 `src\deploy\`。
`python -m uvicorn src.service.main:app` 里的点号是**模块路径**，不是文件名。
`src/service/main.py` ↔ `src.service.main`。

**常见报错**

| 报错 | 意思 | 怎么办 |
|---|---|---|
| `ModuleNotFoundError: No module named 'xxx'` | 没装，或装到了别的 Python | `python -m pip install xxx` |
| `SyntaxError: invalid character '，'` | 代码里混了中文标点 | 换成英文逗号 |
| `UnicodeEncodeError: 'gbk' codec` | 往控制台打中文崩了 | 文件头加 `sys.stdout.reconfigure(encoding="utf-8")` |
| 卡住十几分钟没动静 | 源太慢 | 换镜像，别干等 |

## 4. Docker Desktop

**定位**：把"装 Python + 装 PG + 配环境"打包成一条命令。
你已经手工装过一遍 PostgreSQL，Docker 就是把那九步变成一步。

**怎么开**

```
开始菜单搜 "Docker Desktop"  → 双击
或者命令行：Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"
```

> ⚠️ **必须等托盘鲸鱼图标停止转动**（约 20–30 秒）。图标在动的时候敲命令会报
> `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`。
>
> **这个报错的意思不是"没装"，是"引擎没起来"。**

**三条救命命令**

```powershell
docker compose ps                 # 两个服务是什么状态
docker compose logs -f --tail 20  # 实时看日志（Ctrl+C 退出）
docker compose up -d              # 后台起来
```

**常用的另外几条**

| 想干什么 | 命令 |
|---|---|
| 停掉但保留数据 | `docker compose down` |
| 连数据库看看 | `docker compose exec db psql -U postgres -d defect` |
| 进容器里敲命令 | `docker compose exec app sh` |
| 看镜像 | `docker images` |
| 看真实资源占用 | `docker stats --no-stream` |
| 重新构建 | `docker compose up -d --build` |

**记住这个心智模型**

```
docker        = 客户端（你敲的命令）
dockerd       = 后台引擎（真正干活的）
docker compose = 按 docker-compose.yml 批量管理多个容器
```

`psql` 和 `pg_ctl` 的关系完全一样：`psql` 是客户端，`pg_ctl start` 才是启动服务。
**"客户端连不上"和"服务没开"是两件事**，先分清再排查。

## 5. PostgreSQL（注意：你机器上有两份）

这是最容易被问倒的地方，先说清楚。

| | 本机免安装版 | Docker 里的 |
|---|---|---|
| 位置 | `F:\pgsql\data` | 容器卷 `pgdata` |
| 端口 | 5432（宿主机） | 5432（容器网络内，没映射出来） |
| 现在状态 | **没运行** | 跟着 `docker compose up` 一起起 |
| 谁在用 | 你练 SQL 时 | 演示页 `/detect` 落库时 |
| 客户端 | `F:\pgsql\pgsql\bin\psql.exe` | `docker compose exec db psql` |

> **面试标准答案**："本机装过一个免安装版用来练 SQL；演示环境里换成了容器内的 PostgreSQL，
> 两条路径共用同一套建表 SQL，只是驱动从 sqlite 换成 psycopg。"

### 5.1 本机版怎么开

```powershell
$pg = 'F:\pgsql\pgsql\bin'

# 启动
& "$pg\pg_ctl.exe" -D F:\pgsql\data -l F:\pgsql\server.log start

# 看状态
& "$pg\pg_ctl.exe" -D F:\pgsql\data status

# 连进去
& "$pg\psql.exe" -U postgres -d defect

# 停
& "$pg\pg_ctl.exe" -D F:\pgsql\data stop
```

> `-D` 是数据目录，`-l` 是日志文件。**忘了 `-D` 就会报"没有指定数据目录"。**

进去之后能敲的：

```sql
\dt                              -- 有哪些表
\d inspection                    -- 表结构
select * from inspection limit 5;
\q                               -- 退出
```

### 5.2 容器版怎么连

```powershell
docker compose exec db psql -U postgres -d defect -c "select count(*) from inspection;"
```

**常见报错**

| 报错 | 意思 | 怎么办 |
|---|---|---|
| `Connection refused (0x0000274D/10061)` | 服务没开 | 先 `pg_ctl start` |
| `psql: 无法识别的选项` | 用错客户端了 | 用全路径 |
| `relation "inspection" does not exist` | 连的库不对 | `-d defect` |

**定位**：把"眼睛看到的缺陷"变成"机器能读的坐标"。**项目里所有 AI 效果的源头。**

**怎么开**

```powershell
cd F:\defect-vision
labelme data\annotate --labels labels.txt
```

参数说明：`data\annotate` 是要标的图片目录，`--labels labels.txt` 是预置标签（避免手打错字）。

**操作流程**

| 动作 | 按键 |
|---|---|
| 下一张 | `d` |
| 上一张 | `a` |
| 画多边形 | `Ctrl + N` → 逐点单击 → **点回第一个点**闭合 |
| 保存 | `Ctrl + S` |
| 删掉画错的 | 选中 → `Delete` |
| 撤销 | `Ctrl + Z` |

> ⚠️ **按键前必须先用鼠标点一下窗口。** OpenCV/Qt 的窗口不聚焦时收不到键盘事件——
> 你之前遇到的"按键没反应"就是这个原因。

**标完检查**

```powershell
python src\data\labelme2yolo.py --dry-run
python src\data\check_labels.py
```

**三个铁律**（都在 `docs\标注规范.md` 里）

1. 一个缺陷一个多边形，跨棱线不拆
2. 良品图也要存（生成空的 `.txt`）
3. 看到折痕、背景纹理**不要标**——那是良品也有的东西

## 7. 浏览器 —— 不只是用来看页面

| 看什么 | 在哪 |

| 返回了什么 JSON | 点 `detect` → Response |

## 10. 面试现场：5 分钟从零起全套

按这个顺序，一步都不能跳，每一步都有验证：

```powershell
# ① 进项目
cd F:\defect-vision

# ② 开 Docker Desktop（等鲸鱼停止转动）
Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"
Start-Sleep -Seconds 25

# ③ 起服务
docker compose up -d
docker compose ps                 # 期望：两个 Up (healthy)

# ④ 验证后端真的活着
Invoke-RestMethod http://127.0.0.1:8010/health | ConvertTo-Json

# ⑤ 开演示页
Start-Process http://127.0.0.1:8010/
```

第 ④ 步的输出要能看到这三行：

```
db         : postgresql
model_name : onnx:best.onnx
is_mock    : False
```

**`is_mock: False` 是关键。** 如果是 `True`，说明模型没加载上，你现在演示的是假结果。

## 11. 出问题时怎么查（顺序很重要）

**永远按这个顺序，不要跳步：**

```
① 进程在不在？      Get-Process python ; Get-Process -Name "com.docker.backend"
② 端口在不在听？    Get-NetTCPConnection -LocalPort 8010 -State Listen
③ 接口通不通？      Invoke-RestMethod http://127.0.0.1:8010/health
④ 日志说什么？      docker compose logs --tail 50
⑤ 才轮到改代码
```

> **面试金句**：*"我从外往里查：先确认端口有没有人听，再看接口返回，最后才看日志。
> 大部分人反过来——先看日志，结果绕一大圈发现服务根本没启动。"*

**端口被占用的处理**

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen |
  Select-Object -ExpandProperty OwningProcess |
  ForEach-Object { Stop-Process -Id $_ -Force }
```
