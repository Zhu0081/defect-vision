## L1 · 改一个数，看变化（5–10 分钟）

> 目的：建立"我动的这一下，系统哪里变了"的因果感。

### 1. 把线程数从 8 改成 4

改 `src\service\detector.py` 里这个默认值：

```python
n_threads = int(os.getenv("DV_THREADS", "8"))
```

但**先别改代码**，用环境变量更快：

```powershell
$env:DV_THREADS = "4"
```

然后重启服务，传同一张图 5 次，记下耗时。再换回 8，再传 5 次。

**验收**：你能说出 4 线程比 8 线程慢多少毫秒，以及"为什么"。

---

### 2. 把阈值调到 0.9，看缺陷怎么消失

打开 `http://127.0.0.1:8010/`，在「阈值」框里填 **0.9**，传那张划痕图。

**验收**：缺陷数从 2 变成 0，页面显示 OK。**这就是"阈值太高导致漏检"的现场。**

然后填 **0.05**，传良品图。

**验收**：良品图上出现了假缺陷。**这就是"阈值太低导致过杀"的现场。**

> 两个方向都被你看过一次之后，"阈值扫描"这件事你一辈子不会忘。

---

### 3. 让一张良品图"变成不良品"

拿一张良品纸，用马克笔划一道，重新拍，传进页面。

**验收**：`verdict` 从 ok 变 ng。

---

### 4. 故意传一张非图片文件

传一个 `.txt` 或者 `.py` 文件进去。

**验收**：看到一条明确的错误提示（不是我改过的报错，是你自己撞出来的）。

---

## L2 · 自己跑通一段流程（20–40 分钟）

> 目的：这些命令以前是我敲的，现在你敲。

### 5. 从零把服务起一遍

```powershell
cd F:\defect-vision
# ① 确认 Docker 引擎活着
docker version
# ② 起服务
docker compose up -d --wait
# ③ 验证后端
Invoke-RestMethod http://127.0.0.1:8010/health | ConvertTo-Json
# ④ 开页面
Start-Process http://127.0.0.1:8010/
```

**验收**：`/health` 输出里 `is_mock` 是 `False`。
**如果看不到 Server 段**（第②步之前就报 `failed to connect`）→ 去开 Docker Desktop，等鲸鱼停止转动。

---

### 6. 用 psql 按光源分组统计

```powershell
docker compose exec db psql -U postgres -d defect -c "SELECT light, count(*) FROM inspection GROUP BY light;"
```

**验收**：输出里有 `side` 这一行，数字是多少。

---

### 7. 把两张表 JOIN 起来

```powershell
docker compose exec db psql -U postgres -d defect -c "SELECT i.id, i.filename, d.cls, d.score FROM inspection i JOIN defect_item d ON d.inspection_id = i.id ORDER BY i.id DESC LIMIT 10;"
```

**验收**：同一张图出现多行（每行一个缺陷）。**这就是"一对多"的样子。**

---

### 8. 从日志里找到刚才那次检测

```powershell
docker compose logs --tail 30 app
```

**验收**：找到 `[detect] id=xx verdict=ng 缺陷=2 耗时=xxx ms` 这一行，并且 `id` 对得上你刚才查数据库看到的那条。

---

### 9. 自己提交一次代码

随便改一个东西——比如 README 里改个错字。

```powershell
git status
git diff
git add README.md
git -c core.quotepath=false commit -m "docs: 修正一处错字"
git push gitee main
```

**验收**：GitHub 和 Gitee 网页上都能看到这次提交。

---

### 10. 训练一次模型，改个参数

```powershell
python src\train\train.py --epochs 5 --imgsz 640 --name my_test
```

**验收**：跑完能在 `runs\segment\my_test\` 看到 `results.png`，而且你能说出"5 轮和 30 轮的结果差在哪"。

> 跑 5 轮只要 1 分钟，适合随便玩。

## L3 · 我给你造故障，你来查（30–60 分钟）

> **这是最接近面试的练习。** 面试官问"服务挂了怎么查"，你答"我查过 5 次"比"我看过书"强得多。
>
> 玩法：你说一声，我就把某个东西改坏（不改代码逻辑，只改配置/环境）。
> 你从现象出发排查，我只回答"是/不是"，不提示方向。

### 11. 故障一：服务起不来

**难度**：★★

### 12. 故障二：页面能打开，但传图报错

**难度**：★★

### 13. 故障三：能检测，但结果全是 OK

**难度**：★★★

### 14. 故障四：耗时突然从 300 ms 变成 1.5 秒

**难度**：★★★

> 每做完一个，我告诉你我做的是什么手脚，你自己补进错题本。
